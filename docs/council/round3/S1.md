# S1 round 3 (applied crypto)

**1. Biggest hole: the quorum is not cryptographic.** Questions stay wrapped under a KEK on the same VM forever, and the five shares sit in plaintext on the server until claimed. Any read bug or root yields the paper with zero key holders, and any three unclaimed share rows rebuild the key. Claiming is also a race: whoever logs in first as a holder picks the passphrase and takes the card. "No single person" holds only for UI roles.

**2. Cut too far**
- Seed: logging only H(seed) proves nothing. Reveal it at Close with a "replay draw" check, and keep it out of the permutations. Dropping commit-reveal is fine.
- Hand-posted head: the DB owner can recompute a plain chain, so only witnesses help. Show the head on every approval and print screen. Key the chain (HMAC, one line), length-prefix fields, append in one transaction.
- Show the seat count to approvers and bind it into the two-word check. G3's limit is set by the same account, so it is accounting, not a gate.

**3. Not cut far enough**
- Per-question keys plus wrapping buy nothing once ciphertexts are deleted at Seal. Encrypt under HKDF(KEK, "q|exam"), random 96-bit IV, AAD exam|question|version.
- 2^521-1 Shamir is fine if coefficients are 66 random bytes with the top 7 bits masked and all-ones rejected, x is distinct in 1..5, and test vectors exist.
- Copy ID: seat, reprint number, tag of at least 40 bits, keyed by HKDF(KEK, "copyid|exam"). Orders: HMAC-DRBG, fresh 256-bit key, rejection sampling, stored at print. Trace must check that order and ID agree, since a leaker can copy a neighbour's ID.

**4. Verdict: ACCEPT WITH CHANGES.**
1. Seal is one transaction: decrypt the drawn questions, encrypt the paper under a fresh K, split, **delete every question ciphertext**, zeroize. Shares are never stored in plaintext. Minimum: wrap them under the KEK, delete on claim (0.1 d). Better: replace "claim" with enrol-before-Seal, where the holder's browser makes an ECDH key held under their passphrase and the server wraps each share to it (0.5 d). This also removes the race. **User decides.**
2. Seed reveal and replay (0.25 d).
3. Head witnessing and keyed chain (0.25 d).
4. Drop per-question keys (saves 0.25 d).
5. Seat count shown and bound (0.1 d).
6. Practice: banner, `practice` flag settable only by the seed script (0 d).

Limits: root or substituted JavaScript, pre-Seal snapshots, HTTPS only.
