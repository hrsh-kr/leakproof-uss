# A3 (Thiel lens), Round 3: attack on the minimal system

Role-played lens, not the real person.

## 1. Biggest hole: the 10x feature was demoted to one route line
The whole bet is "cropped photo, named seat". In `11` it is `GET /exams/:id/trace?order=...`, after close, with no matcher spec. `10` admitted the current `traceSeats` matches a fixed prefix only, so a cropped photo fails. If the windowed matcher is not built, the live demo shows the trace failing on exactly the input the professor will try.

Two further problems on the same route:
- The pasted order travels in a URL query string, so paper content lands in access logs, and the canary scan fails on our own code.
- The exam cell traces, but the exam cell also prints every copy. A pre-exam photo leaked from the print room traces to seat 17, so an innocent candidate is named. "Exam cell cannot read content because no screen shows it" is false: `/copies` shows all of it.

## 2. Cut too far
- **Windowed matcher with a test on 3-question fragments.** It is the product. Losing it loses P3 and the differentiator.
- **The demo's pre-built state.** A released exam with 60 copies and a prepared cropped photo must survive a reset. Do not rely on the live flow.
- **Honest practice mode.** Each tester holds all five cards, so P1 ("no one person reads the paper") is false in practice mode. Testers will report that as a vulnerability. Label it "single-person practice; quorum is real only on the demo exam".

## 3. Not cut far enough
- **CLOSED stage.** Remove it and allow trace once RELEASED. This saves a state, a route and a demo step.
- **Key card with a browser passphrase and a two-word check.** This is the most step-heavy ritual, and Phase I's complaint was step count. Keep it only if it works by the end of 14 Nov. Otherwise use the server-wrapped fallback (already last in the `10` cut order) and say so.
- **80 shared-package accounts.** Testers will log into each other's accounts. Say this in the guide so it is not filed as a finding.

## 4. Verdict: ACCEPT WITH CHANGES
Ranked changes, with day cost:
1. Specify the windowed matcher as the acceptance test: the 3-question fragment, a cropped header and a shuffled-neighbour negative test. Make it `POST /exams/:id/trace`, not GET. **+0.75 d** (offset by item 3).
2. Rewrite the exam cell claim honestly. The cell sees content at print time. A trace is a lead, and a pre-seat leak implicates the print chain. Add one log line recording who fetched `/copies`. **0.1 d.**
3. Drop CLOSED and trace at RELEASED. **-0.25 d.**
4. Script the 26 Nov demo as a recorded fallback, with a seeded released exam and a cropped-photo asset. **0.25 d.**
5. Add a tester-guide note: shared-account behaviour and practice-mode quorum are known and out of scope. **0.05 d.**

## The question still avoided
A trace names a seat, not a person, and the system holds no seat-to-student mapping. The likeliest leaker is the staff member holding all 60 copies for hours, not a candidate. So who is actually deterred, and would any teacher or exam officer, none of whom Phase I reached, run this? State it in Part B as a limit before a classmate finds it.
