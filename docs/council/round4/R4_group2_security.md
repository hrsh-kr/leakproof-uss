## 2. Their security mistakes (with evidence)

Ordered by what a classmate could actually exploit.

1. **The socket flood (the one Valid bug, G2-#44).** Root cause: they relied on `limit_conn conn_limit 15` (`nginx/nginx.conf:48`), which only counts connections whose request header has been read. An idle or slow-socket flood never reaches that point. With no `client_header_timeout`, `keepalive_timeout` or `reset_timedout_connection` (none anywhere in `nginx/`), the defaults keep junk sockets for 60 to 75 s. With no `iptables connlimit` or syncookies, one host could fill nginx's worker connection table. Their own reply was "NO REBUTTAL… site was actually down for users at other IP address". A secondary factor: Argon2 runs on the event loop (`services/auth_service.py:101-108` called from `async def` routes), so a login flood also serialises everything.
2. **A self-registrable read-only admin gives cross-user data access** (`schemas/auth.py:32`, `routes/auth.py:106-110`). It exposes all emails and last-seen IPs (`routes/admin.py:38-79`), the audit log with emails in `details` (`:313-350`), any resume download (`routes/resumes.py:158-180`), any resume text preview with no step-up (`:306-340`), and a bypass of every privacy setting (`routes/users.py:577-585`). Three reports (G2-#23/#24/#29) were ruled Invalid only because it was "instructor-requested". Lesson: a self-service account must never see other users' data, even read-only.
3. **Rate caps count the wrong event.** `check_action_rate_limit` runs before the attempt, but `record_action` runs only on success for `login` (`routes/auth.py:214, 250`) and `forgot_password` (`:484, 520`). Failed guesses are never counted. The rebuttals to G2-#17/#19 cite "Login: 50/day per IP" as brute-force protection.
4. **The lockout key is wrong in both directions.** By IP on `/verify-totp` (`routes/auth.py:282-286`), so rotating IPs bypasses it (G2-#20, and the rebuttal concedes the point). By the victim's **email** on forgot, change and delete (`:413-420, 492-506, 562-569`), with 60 min ×5 escalation that never decays (`services/totp_service.py:24-32, 77-84`), so a stranger can lock a victim out of recovery for 1 h, then 5 h, then 25 h.
5. **The audit chain gives no real tamper evidence.** It is an unkeyed SHA-256 chain with no external anchor (`services/audit_service.py:19-31`). Concurrent appends can likely fork it (`:34-46`). A foreign key with `ON DELETE SET NULL` on `audit_logs.user_id` (`models/audit.py:17`) means every user deletion mutates hashed rows, and the verifier then reports tampering. The proof-of-work "blockchain" (`services/blockchain_service.py:23`) adds nothing.
6. **Crypto fails open.** The TOTP secret falls back to plaintext and decryption returns its input on any error (`services/totp_service.py:141-158`). An ephemeral in-memory Fernet key is generated when none is configured (`main.py:94-100`). The default JWT secret goes unchecked (`config.py:17`).
7. **Password change does not end other sessions**, despite its comment (`routes/auth.py:423-430`). Only forgot-password sets `force_reauth_at` (`:509`). The WebSocket ignores `force_reauth_at` entirely (`routes/websocket.py:26-49`).
8. **The logout CSRF rebuttal contradicts the code.** `/logout` has no auth and always answers 200 with cookie deletions (`routes/auth.py:525-541`). The G2-#39 rebuttal claims a cookieless cross-site call "returns 401".
9. **The user-enumeration defence is inverted.** An unknown email does two Argon2 operations (`routes/auth.py:219-221`). Register also answers 409 for a taken email (`:88-93`).
10. **IDOR in the skill-match route.** The recruiter is authorised on `job_id`, not on the resume's applications (`routes/resumes.py:359-376`).
11. **The privacy filter is a deny-list** (`routes/users.py:556-590`), and the settings dict is replaced wholesale on update (`:450-452`). Fields absent from the dict are shown.
12. **Provisioning hands over the newcomer's second factor.** `create-admin` returns the TOTP secret to the creator (`routes/admin.py:233-241`). `seed_admin.py:78-83` prints the password and TOTP secret to the terminal.
13. **Too much trust.** `X-Forwarded-For` is trusted unconditionally (`utils/ip.py:16-19`), and the dev runner binds `0.0.0.0` (`serve_https.py:34-37`). CORS and the WebSocket `Origin` check accept every `https://192.168.x.x` (`main.py:184`, `routes/websocket.py:100`).
14. **Per-IP caps hurt legitimate users behind shared IPs.** A day scholar on the institute VPN could not register at all, because of "5/week per IP" (G2-#11). 30 API requests/min per IP (`nginx.conf:2`) is low for a SPA behind NAT. The "site is down" reports G2-#17/#19 were answered with "your IP hit the rate limit". Those reports were ruled Invalid, but the users saw the site as down.
15. **Host exposure.** A tester's nmap showed RDP 3389 open on the VM (G2-#22). The team disputes it, and the repo contains no firewall.
16. **Overclaims.** `ARCHITECTURE.md` lists "CSRF tokens" (none exist) and "admin = full platform management". The rebuttal to G2-#20 states lockout parameters ("5 → 15 min") that the code does not implement. `X-XSS-Protection` and the shuffled keypad (`VirtualKeyboard.jsx:31-35`, `Math.random`) are security theatre.
17. **Minor issues.** TOTP codes can be replayed within the window (no used-code store, `totp_service.py:181-187`). `.env.example` sets `DEBUG=true` (`backend/.env.example:27`). The decrypted private key sits in `sessionStorage` (`e2eeKeyStore.js:194`). The WebSocket token travels in the query string.

### ADOPT / ADAPT (most valuable first)

1. **ADAPT: per-IP caps must survive shared campus NAT and VPN (lesson from G2-#11, #17, #19).** Attack week is exactly when dozens of classmates hit us from a few hostel or VPN addresses. Our per-IP auth bucket is 10/min in the app (`src/config.mjs:23`) and 10 r/min burst 5 in nginx (`deploy/nginx.conf:5, 47`). Registration is 5/day per IP (`src/config.mjs:24`). Honest testers would lock each other out, and it would look like a DoS against P5 and usability. Brute-force resistance does not come from these buckets: it comes from 80-bit generated passphrases and the `username|ip` backoff. **How:** raise `LP_AUTH_PER_MIN` to about 60 and the nginx `lp_auth` zone to about 60 r/m burst 20; raise `LP_REGISTER_PER_IP` to about 30 (the invite code plus `maxAccounts` 300 cap the total). Make the 429 text say "Many people on your network are signing in; try again in N seconds".
2. **ADOPT: make the firewall persistent and default-deny the other ports (G2-#44 root cause, G2-#22 RDP).** `deploy/firewall.sh` runs once from `install.sh:35`. `iptables -I` does not survive a reboot, and `deploy/` is not copied to `/opt/leakproof` (`install.sh:8`). After a VM reboot the `connlimit` that answers G2's only valid bug is gone. **How:** copy `deploy/firewall.sh` in `install.sh`, and add `ExecStartPre=+/bin/bash /opt/leakproof/deploy/firewall.sh` to `leakproof@.service` (the rules are idempotent via `-C`). Append rules that accept `lo`, ESTABLISHED, 22, 80 and 443 and drop the rest (open 8443 on 25 Nov). Set `PasswordAuthentication no` for SSH. Test SSH in a second session before logging out.
3. **ADOPT (process): rehearse G2's valid attack on the real VM before 17 Nov.** Our flood test (`tests/security.test.mjs:229`) exercises the in-process app only. The nginx + iptables layer that actually stops a 1M-socket flood is untested. **How:** from a second machine, open about 2,000 idle TLS sockets plus a slow-header flood, check `/healthz` from a third address, and save the output to the evidence folder. Twenty minutes, and it directly answers the one bug class that was ruled Valid against G2.
4. **ADAPT: the provisioner must not keep working credentials for key holders (lesson from G2 mistake #12).** `scripts/official-setup.mjs:29` prints every official passphrase and recovery code to the operator's terminal. One operator could log in as all five holders and claim all five cards, breaking P1 with a single person. **How (official instance only):** the first login on an account the operator created forces rotation. The server shows a fresh passphrase and recovery code to the holder, the printed ones stop working, card fetch is refused until rotation is done, and the chain logs `account.activated`. A front-run then becomes visible, because the real holder's slip stops working and the log shows it. About 0.25 day. The official instance is not attacked by classmates, so this ranks after items 1 to 3. If time runs out, state it as a limit in `SECURITY.md` section 4.
5. **ADAPT: background polling must not count as activity (G2 has no idle logout, #40; ours is defeated).** The Release page polls every 5 s (`public/app.js:278`), and `session()` refreshes `seen` on every request (`src/app.mjs:35`). An exam-cell screen left open never idles out until the 8 h absolute limit. **How:** the poll sends a header such as `X-Poll: 1`, and `session()` skips the `UPDATE ... seen` when it is present (2 lines).
6. **ADOPT (small): an honest `Retry-After` (G2's client reads it, `frontend/src/services/api.js:31`).** We always send `Retry-After: 60` (`src/app.mjs:292`), but the limiter already computes the real reset (`src/http.mjs:81`). **How:** attach `retry` to the `HttpError` thrown at `src/app.mjs:256/259/267` and send it, and show it in the message. Helps users under item 1.
7. **ADOPT (small): verify health after deploy (G2 `start.sh:29-48, 98-109`).** **How:** end `deploy/install.sh` with a 20-try loop of `curl -fsk https://127.0.0.1/healthz || sleep 1`, and exit non-zero with "check journalctl -u leakproof@practice" on failure.
